# Fiscal Overhaul

A Cities: Skylines II mod that replaces the Economy panel's budget bar chart with a filterable time-series line chart and adds density-based taxation. C# mod in `Mod/` (the game's csiimod toolchain), TypeScript/React UI module in `UI/`, xunit tests in `Tests/`.

## Testing rule

- **Every feature ships with tests**, and every bug fix with a regression test; each test has a pass case and a fail case. The request is the test contract.
- **Pure logic lives in testable classes** (`Mod/Logic/`, plain TS modules beside their components), so tests need neither the game nor the UI host ([patterns.md § Pure logic](knowledge/patterns.md#pure-logic)).
- **UI changes need an in-game screenshot**, looked at, before the work is done: [the in-game check](knowledge/testing.md#the-in-game-check) deploys, opens the Economy panel and judges it. `/playtest` is the other direction: it files the user's own playtest notes as issues.
- Run: `./tools/build.ps1 -NoDeploy` (compile check) and `./tools/test.ps1` (xunit and vitest) as you work; `./tools/build.ps1` deploys ([testing.md § Running tests](knowledge/testing.md#running-tests)). The game is one shared instance: never deploy or launch it while another session holds it ([orchestration.md](knowledge/orchestration.md#the-shared-game-instance)).

## Git workflow

Work branches are `feature/<kebab>` or `fix/<kebab>`; `master` changes only through PRs titled `vX.Y.Z - <summary>`, which the user merges. Enable the hooks once per clone: `git config core.hooksPath .githooks`. Problems outside the task become GitHub issues ([issues.md](knowledge/issues.md)), not fixes in passing.

**Autonomous work goes through `autodev`** (the global `/autodev` skill; batches: `/orchestrate`): branch from `origin/autodev`, test, `gh pr create --base autodev --body-file <file>`, then land it yourself with `./tools/land-pr.ps1 <n>`. Never merge any other way, never force-push or delete `autodev`. The user tests `autodev` in game and promotes it (`/promote`). Details: [git-workflow.md](knowledge/git-workflow.md#autonomous-sessions-autodev).

## Architecture

- **C# side publishes, UI side draws.** `Mod/Systems/*UISystem.cs` expose bindings in the `"fiscalOverhaul"` group
  (`history`, `setSpan`, `densityTaxes`, `setDensityTax`) and compute only while the Economy panel is open. The UI
  reads them through `UI/src/bindings.ts`, alongside the vanilla `economyBudget`/`taxation` bindings.
- **Budget tab:** `BudgetHistoryUISystem` turns the game's saved per-source income/expense statistics into per-month
  series; `UI/src/budget/budget-page.tsx` overrides vanilla `BudgetPage` and draws `UI/src/chart/line-chart.tsx` (canvas).
  [impl/budget-chart.md](knowledge/impl/budget-chart.md)
- **Density taxes:** an apply/restore system pair around vanilla `TaxSystem` adds each building's density offset only
  while tax is charged; offsets live in `Setting.DensityTaxOffsets`; the Taxation tab extends vanilla `TaxationGroup`.
  [impl/density-taxes.md](knowledge/impl/density-taxes.md)
- **Pure logic** (`Mod/Logic/`, `UI/src/chart/chart-math.ts`, `UI/src/taxation/density.ts`) carries the maths and is
  what the unit tests cover.

## CS2 modding

The traps, in short ([cs2-ui-modding.md](knowledge/cs2-ui-modding.md) has the details):
- **Launch the game through Steam** (`steam://rungameid/949230`), never `Cities2.exe` directly: without the platform
  integration it hangs at startup. The game doesn't hot-reload mod UI; a restart loads a new build, and a running game
  locks the DLL, so deploy only while it is closed.
- **The UI is laid out for 4K**: 1rem is under a pixel below 4K. Canvas drawing must scale by px-per-rem, measured
  from a `100rem` probe.
- **Gameface is not Chrome**: canvas 2D yes, inline SVG no, no `ResizeObserver`, patchy `Intl`.
- **Vanilla UI is reused through `getModule`/`override`/`extend`** with the module paths in `UI/src/vanilla.ts`.
- **Simulation systems** inherit a vanilla system's update offset only with the same interval and `UpdateBefore/After`.
